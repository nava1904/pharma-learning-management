Employee Portal
Redesign Prompt

A complete, production-grade specification for rebuilding the Pharma LMS Employee Portal — fully connected to the Serverpod backend, applying all top-tier design principles.

Flutter 3.x + Riverpod
Serverpod + PostgreSQL
21 CFR Part 11 Compliant
WCAG AA Accessible
8 Screens · 14 Fixes

The primary user is a pharmaceutical employee — lab technician, quality associate, production operator — who must complete mandatory compliance training on time. Late training is a regulatory violation. The product must communicate urgency, trust, and clarity at every pixel.

This is NOT a generic LMS. It is a compliance-critical, audit-ready platform where every interaction is logged, every certificate is legally significant, and every overdue item carries regulatory risk.

§ 02

Design Principles

Apply ALL of the following simultaneously. Every screen must pass each principle before it is considered complete.

```
Apple HIG Clarity · Deference · Depth
  • Clarity: Legible text at every size. Min tap target 44×44pt. No orphaned text.
  • Deference: UI recedes — the course, certificate, and due date are always the hero.
  • Depth: 4-layer system — background → cards → elevated modals → overlays. Each layer has its shadow token. Never mix layers.
  • 8pt Grid: Every spacing value is a multiple of 8. (4px for micro-gaps only)
  • Motion: Page transitions 280ms ease-out. Skeletons replace spinners. Spring physics for sheets (stiffness 400, damping 35).
Refactoring UI Hierarchy · Spacing · Typography
  • Use size, weight, and color — not borders or boxes — to create hierarchy.
  • Every screen has exactly ONE primary action, ONE secondary, rest tertiary.
  • Space = relationship. Closer items are more related. Section gaps are generous (48px+).
  • Display: Bricolage Grotesque 700 / Title: 600 / Body: DM Sans 400 / Code: JetBrains Mono
  • One primary color, semantic danger/success/warning, everything else is neutral grey.
Don't Make Me Think One Action · Self-Evident · Recovery
  • One obvious next action per screen. Never equally-weighted choices.
  • One navigation system — sidebar = primary navigation, topbar = context breadcrumb.
  • Any user understands what to do within 3 seconds of landing on any screen.
  • Errors always say what went wrong AND how to fix it. Never raw exceptions.
Laws of UX Fitts · Jakob · Hick · Miller · Doherty
  • Fitts: Primary CTAs min 48px tall. Danger items are RED, not just larger.
  • Jakob: Familiar patterns — course cards look like course cards. No novel interactions.
  • Hick: Max 5 items on dashboard before "View all →". Max 7 sidebar nav items.
  • Miller: Max 4 stats on dashboard. Badges >99 show "99+".
  • Doherty: Skeleton within 100ms. Never blank white screen during any API call.
UI is Communication Colour Semantics · Human Dates · Empty States
  • OVERDUE = RED. Not orange. Not yellow. Red = danger = regulatory risk.
  • COMPLETED = GREEN with checkmark. PENDING = BLUE. These are non-negotiable.
  • Dates are ALWAYS human: "Mar 11, 2026" — never "2026-03-11".
  • Status labels are ALWAYS human: "Not Started" — never "NOT_STARTED".
  • Empty states explain why it's empty AND what to do next.
Designing with the Mind in Mind Affordance · Feedback Loops · Recognition
  • Buttons look like buttons. Inputs look like inputs. Locked items show padlocks.
  • Every action has a response within 100ms: tap → scale(0.97), API → skeleton, success → checkmark animation.
  • Recognition over recall — show course name in breadcrumb, show previous score before retake.
```

API Contracts (Serverpod)

// All endpoints require: Authorization: Bearer {accessToken}
// All responses: { data, meta: { requestId, timestamp } }
// All errors: { error: { code, message } } — NEVER raw stack traces

class EmployeeEndpoint extends Endpoint {
// Single dashboard call — no N+1
Future<DashboardSummary> getDashboard(Session session);

Future<List<TrainingAssignment>> getTraining(
Session session, {
TrainingStatus? status,
String? search,
TrainingSortBy sortBy = TrainingSortBy.dueDate,
});

// Returns 422 with friendly error if courseVersionId is null
Future<CourseDetail> getCourse(Session session, String courseId);

// Progress update — call every 30s during lesson
Future<ProgressUpdateResult> updateLessonProgress(
Session session, String lessonId,
double progressPercent, int secondsViewed,
);

Future<AssessmentResult> submitAssessment(
Session session, String assessmentId,
List<AssessmentAnswer> answers,
);

Future<List<Credential>> getCredentials(
Session session, {
DateTime? from, DateTime? to,
String? status, String? search,
});
}

§ 11

Compliance & Audit (21 CFR Part 11)

Every user action that touches training records MUST fire a Kafka event. These events are the foundation of regulatory compliance.

// Kafka events — fired via Serverpod endpoint, never directly
LESSON_OPENED:      { userId, courseId, lessonId, timestamp, ip }
LESSON_PROGRESS:    { userId, lessonId, percent, secondsViewed }
LESSON_COMPLETED:   { userId, lessonId, completedAt, totalSeconds }
ASSESSMENT_STARTED: { userId, assessmentId, timestamp }
ASSESSMENT_ANSWER:  { userId, questionId, answerId, timestamp }
ASSESSMENT_SUBMITTED: { userId, assessmentId, score, passed }
CERTIFICATE_VIEWED:    { userId, certificateId, timestamp }
CERTIFICATE_DOWNLOADED:{ userId, certificateId, timestamp, format }

// Timestamps: stored UTC, displayed local time (human format)
// SCORM: capture cmi.completion_status via postMessage bridge
§ 13

Bugs to Fix (All 12)

BUG-001Critical
"Missing course version" hard crash screen with no recovery.
→ Fix: validate courseVersionId before navigation. Return 422 with friendly message. Never blank/broken screen.
BUG-002Critical
Course content area is a black void — primary task blocked.
→ Fix: loading skeleton → PDF/video/SCORM content. Never render #000 background.
BUG-003Critical
"Take Assessment" permanently disabled with no explanation.
→ Fix: hover tooltip "Finish reading to unlock". Animate to enabled state when lessons complete.
BUG-004Major
100% completion ring contradicts OVERDUE status — data contradiction destroys trust.
→ Fix: replace orphan ring with 4 labelled stat cards. Compliance % ≠ overdue status.
BUG-005Major
Dates as ISO "2026-03-11" throughout the app.
→ Fix: apply DateDisplay.humanDate extension everywhere. Search & replace all DateFormat patterns.
BUG-006Major
Status as "NOT_STARTED", "IN_PROGRESS" — raw DB enums shown to users.
→ Fix: TrainingStatusDisplay.label extension. Never pass .name to any Text widget.
BUG-007Major
Credentials Wallet always empty — no guidance, no data.
→ Fix: show real credential cards. Add meaningful empty state with "Complete a course to earn your first certificate".
BUG-008Moderate
Dual navigation — topbar and sidebar both navigate.
→ Fix: topbar = breadcrumb context only. Remove link behaviour from breadcrumb.
BUG-009Moderate
"Learning" vs "Courses" — unclear distinction in sidebar.
→ Fix: rename to "My Training" (assigned) and "Course Catalog" (browse all).
BUG-010Moderate
Tab bar has no item counts — user can't see urgency at a glance.
→ Fix: count badges on each tab. Red badge if any overdue items in that tab.
BUG-011Minor
Notification badge on logout icon instead of bell.
→ Fix: red badge with count on bell icon only.
BUG-012Minor
Back button position inconsistent — different location per screen.
→ Fix: always top-left of course sidebar, same position every time.
